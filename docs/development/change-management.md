# 变更管理与检查清单

> 文档状态：Current
> 权威范围：不同类型变更的实施、测试和文档同步要求
> 维护触发：新增稳定扩展点或发布门禁

## 1. 通用完成定义

每次变更必须回答：

1. 修改解决了什么问题？
2. 哪个模块拥有该职责？
3. 是否改变外部行为、状态、协议或安全边界？
4. 失败时会发生什么，是否可以恢复？
5. 如何验证，哪些风险暂未覆盖？
6. 哪篇权威文档必须同步更新？

## 2. 变更类型清单

### RPC 或流式事件

- 更新 `src/ipc/models.py` 和 Handler。
- 明确幂等性、重试和断线行为。
- 更新 API 文档与兼容策略。
- 增加 Router、Handler、Transport 和客户端测试。

### Agent 循环、预算或恢复

- 明确 Run、Execution、Slice 的状态变化。
- 检查 Session 锁、并发 slot 和 checkpoint。
- 检查异常是否错误占用 Session。
- 更新 Agent、恢复和数据库架构文档。
- 增加暂停、恢复、丢弃和崩溃恢复测试。

### 数据库 Schema 或持久化

- 使用加法迁移，禁止静默破坏用户数据。
- 明确事务边界、幂等性和回滚方式。
- 更新数据库架构、备份恢复和升级文档。
- 增加旧版本升级、失败回滚和新版本拒绝测试。

### Tool、命令或文件访问

- 明确 ToolAudience 和 ToolRisk。
- 检查 Workspace、路径逃逸、命令注入、超时和输出限制。
- 检查结果是否进入 Prompt、Artifact、Trace 或 Telemetry。
- 增加安全与边界测试。

### 模型 Provider

- 不向业务层暴露具体 SDK。
- 处理配置缺失、流式 usage 和服务商错误。
- 确保错误消息脱敏。
- 更新错误参考和 Provider 架构。

### 后台任务、Telemetry 或 Trace

- 不得进入用户输出关键路径。
- 使用有界队列、超时、失败隔离和关闭 drain。
- 明确数据是否权威、是否允许丢失。
- 增加慢下游、队列满、重启和失败测试。

### 文档或配置

- 更新文档登记表和导航。
- 检查根路径链接。
- 配置变化同步 `.env.example`、配置参考和部署文档。
- 运行 contracts 测试。

## 3. Review 重点

代码审查按以下优先级：

1. 数据丢失、跨 Workspace 泄漏、命令执行和敏感信息风险。
2. 并发竞态、死锁、无限等待和资源泄漏。
3. 协议、Schema 和状态兼容性。
4. 用户延迟与后台任务隔离。
5. 单一职责、依赖方向和测试可替换性。
6. 文档、命名和可读性。

## 4. 合并前检查

```shell
python -B -m unittest discover -s tests -t . -v
git diff --check
```

此外确认：

- 没有提交 `.env`、数据库、日志、Trace 或 token。
- 没有无意覆盖用户未提交修改。
- 已知风险进入路线图，而不是只保留在 PR 评论。
- PR 描述包含验证结果和残余风险。
