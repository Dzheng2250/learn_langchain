# 设计决策记录模板

> 文档状态：Current
> 权威范围：重要架构决策的记录格式
> 维护触发：设计决策管理方式变化

## 本文负责

- 重要设计决策必须记录的问题、方案、取舍、状态和后果结构。

## 本文不负责

- 不记录具体项目决策。
- 不替代 Current Architecture 或 API 文档。


重要、难以逆转或影响多个模块的选择应写入 `docs/decisions/`。决策记录解释“为什么”，不能替代当前
API、Architecture 或 Operations 文档。

```markdown
# 决策标题

> 文档状态：Draft | Current | Deprecated | Superseded
> 决策日期：YYYY-MM-DD
> 影响范围：模块或外部契约
> 替代关系：无，或链接到替代/被替代决策

## 背景与问题

## 优化目标

## 约束与假设

## 候选方案

## 最终决策

## 选择原因

## 缺点、风险与缓解方式

## 实施和迁移

## 验证方式

## 重新评估触发条件
```

当决策被替代时：

1. 保留原文。
2. 将状态改为 `Superseded`。
3. 链接新决策。
4. 更新 Architecture 和文档登记表。
