# 文档模板

> 文档状态：Current
> 权威范围：新增 Current 文档的最低结构要求
> 维护触发：文档治理规则变化

新增文档时复制以下结构，并删除不适用章节。文档必须描述已经实现的事实；尚未实现的内容应明确标记为
`Planned` 或登记到路线图。

```markdown
# 标题

> 文档状态：Current | Draft | Historical | Deprecated
> 权威范围：该文档负责回答的问题
> 维护触发：哪些代码或流程变化时必须更新

## 目标与读者

## 本文负责

列出本文作为权威来源负责回答的问题。

## 本文不负责

列出需要跳转到其他文档的问题，避免把别的模块设计复制进来。

## 当前实现

## 数据流或操作流程

## 失败模式与恢复

## 安全、性能与一致性边界

## 当前限制

## 相关文档
```

要求：

- 复杂术语首次出现时使用通俗语言解释。
- Current 文档必须明确“本文负责 / 本文不负责”，尤其是架构文档。
- API 字段、配置默认值和状态值只在其权威参考文档中完整列出。
- 流程说明应写明前置条件、成功结果和失败后的处理方式。
- Mermaid 图应拆分为可阅读的单一主题，不绘制无法维护的超大总图。
- 不复制未来计划冒充当前能力。
